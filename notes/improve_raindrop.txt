Evidence: run score breakdown, belief histories, 13 Raindrop events
Diagnosis: The agent found the true driver (distribution loss) and became confident quickly, but it also created beliefs on units, which is a symptom 
metric. Two of those beliefs were duplicates, and both stayed active at 0.99 and were scored as wrong. Supersede decisions also kept re-proposing 
symptom claims, so wrong beliefs piled up beside the correct one.
  • added rule: Only form hypotheses about causal levers (price, distribution coverage, promotion). Revenue and unit volume are symptoms of the 
decline, not explanations of it, so never use them as the test metric. (Removes the symptom beliefs that cost points for non-causal and wrong active 
beliefs.)
  • added rule: A change in a symptom metric shows that something happened but not why. When volume falls, check which causal lever moved in the same 
period and form the hypothesis on that lever. (Redirects the agent from 'units fell' to the underlying cause.)
  • added rule: Before proposing a new belief, check whether an active belief already tests the same region and metric. If one does, update that 
belief instead of creating another. (Prevents duplicate beliefs.)
  • added rule: When two active beliefs conflict, or one is only a restatement of the observed decline, contradict or supersede the weaker one. Do not
keep several explanations active for the same drop. (Reduces wrong beliefs still active at the end.)
  • added rule: Judge a causal belief by whether its lever changed before or at the same time as the decline began, and whether the size of the change
is consistent with the size of the decline. A lever that stayed flat cannot be the cause. (Gives a consistent test that favors the true driver and 
speeds up confidence in it.)
  • guardrail causal_metrics_only: off → on (Code-level block on units and revenue beliefs removes the symptom beliefs and the wrong active ones.)
  • guardrail no_duplicate_metric_beliefs: off → on (Prevents duplicate beliefs in the same region and metric.)
  • parameter reinforce_boost: 0.15 → 0.2 (Slightly faster confidence gain on supported causal beliefs improves timeliness.)
